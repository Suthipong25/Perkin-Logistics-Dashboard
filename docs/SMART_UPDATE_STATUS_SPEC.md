# Smart Operational Status & Email Timeline Summarizer
## ระบบวิเคราะห์และสรุปสถานะงานอัจฉริยะจากอีเมล (Perkin Logistics)

### 1. วัตถุประสงค์ (Objective)
เปลี่ยนข้อมูลการสื่อสารหน้างานที่กระจัดกระจายอยู่ในอีเมล CS (`cs@perkin-logistics.com`) ให้กลายเป็น **"ข้อความอัปเดตสถานะงาน (Update Status)"** ที่กระชับ ได้ใจความ และเป็นมาตรฐานเดียวกัน โดยใช้ AI ช่วยคิดวิเคราะห์และจัดกลุ่ม เพื่อให้ผู้บริหาร, CS, และทีมปฏิบัติการเปิดอ่านแล้วเข้าใจภาพรวมของงานได้ทันทีภายใน 3 วินาที โดยไม่ต้องเสียเวลาเปิดไล่อ่านอีเมลทีละฉบับ

---

### 2. ปัญหาเดิมที่ต้องแก้ไข (Pain Points)
1. **ภาษาอีเมลกำกวมและยาวเกินไป:** มีทั้งคำทักทาย ลายเซ็น ประวัติการตอบกลับ (Quote threads) และคำย่อเฉพาะทาง (เช่น 0409, DEM, D/O, Free time) ทำให้คนนอกแผนกเข้ามาอ่านแล้วไม่เข้าใจ
2. **ไม่รู้ว่าเรื่องค้างอยู่ที่ใคร:** ข้อความเดิมมักบันทึกแค่สิ่งที่เกิดขึ้นแล้ว แต่ไม่บอกว่า *"ใครต้องทำอะไรต่อ"* ทำให้งานสะดุดและเกิดคอขวด
3. **ภาระการคีย์ข้อมูลซ้ำซ้อน (Manual Burden):** พนักงานต้องทำงานในเมล แล้วยังต้องสลับหน้าจอมาคอยพิมพ์อัปเดตลง Excel หรือระบบอีกรอบ ทำให้ข้อมูลไม่อัปเดตแบบเรียลไทม์

### 3. สถาปัตยกรรมการทำงาน (Architecture & Pipeline)

```
[ Outlook CS Mailbox ]
         ⬇ 1. ดักจับอีเมลใหม่ทุกฉบับ (Microsoft Graph API)
[ n8n Code Filter ]
         ⬇ 2. จับคู่ Job No./BL + ตัดลายเซ็นและคำทักทายทิ้ง
[ AI Reasoning Node (Gemini Flash) ]
         ⬇ 3. วิเคราะห์เนื้อหาและจัดรูปประโยคตาม "สูตร 3 ส่วน"
[ Database (PostgreSQL / SQLite) ]
         ⬇ 4. บันทึก Update Status ล่าสุด + เก็บประวัติ Timeline
[ แดชบอร์ด & LINE Alert ]
         ➔ 5. แสดงผลแท็กสีทันที + แจ้งเตือนเข้า LINE หากเป็นเรื่องด่วน
```

### 4. รูปแบบมาตรฐานของข้อความ (Standard Output Specification)
ทุกข้อความที่ถูกสรุปจะต้องตอบสนอง **"สูตร 3 ส่วน (The 3-Part Formula)"** เสมอ:

$$\mathbf{[หมวดงาน/แผนก]} \ + \ \mathbf{[ข้อเท็จจริงล่าสุด]} \ + \ \mathbf{[สิ่งที่ต้องทำต่อ \ \text{➔} \ ใครเป็นผู้รับผิดชอบ]}$$

#### ตัวอย่างโครงสร้างข้อมูล (JSON Schema):
```json
{
  "job_no": "SI26110048",
  "department": "CARRIER",
  "severity": "CRITICAL",
  "current_fact": "ตู้คอนเทนเนอร์โดนระงับปล่อย มียอด Demurrage ค้างชำระ 4,200 บาท",
  "next_action": "รอฝ่ายบัญชีโอนชำระเงินให้สายเรือเพื่อปลดล็อคตู้",
  "action_owner": "ฝ่ายบัญชี",
  "display_text": "🔴 [สายเรือ/ตู้] ตู้ติด Demurrage ค้าง 4,200 บ. ➔ รอฝ่ายบัญชีโอนชำระด่วน",
  "email_source": {
    "subject": "Re: ติดตามตู้สินค้า B/L ONE50769",
    "sender": "shipping-team@perkin-logistics.com",
    "timestamp": "2026-11-17T10:15:00+07:00"
  }
}
```

### 5. ระดับความเร่งด่วนและการแสดงผล (Visual Severity Levels)

| ระดับ | แท็กสี | ความหมาย | ตัวอย่างสถานการณ์ | การดำเนินการของระบบ |
| :---: | :---: | :--- | :--- | :--- |
| **CRITICAL** | 🔴 สีแดง | **งานติดขัดขั้นวิกฤต** มีความเสี่ยงเสียเงินหรือถูกปรับ | ตู้ติด Demurrage/Detention, ใบขนผิดถูกด่านกัก, เอกสารตกค้าง | แสดงสีแดงบนตาราง + **แจ้งเตือนเข้า LINE กลุ่มทันที** |
| **WARNING** | 🟡 สีเหลือง | **กำลังดำเนินการ / รอคิว** | รอเซลล์สรุปราคา, รอสายเรือคอนเฟิร์มวันเรือเข้า, รอยืนยันคิวรถ | แสดงแถบสีส้ม/เหลืองบนตาราง |
| **NORMAL** | 🟢 สีเขียว | **งานเสร็จสิ้น / ราบรื่น** | ยิงใบขนผ่าน 0409, รถส่งของถึงโรงงานแล้ว, ปิดชุดส่งบัญชี | แสดงแถบสีเขียวบนตาราง |

### 6. ประโยชน์ที่ธุรกิจจะได้รับ (Business Value)
1. **Zero Manual Entry (ลดงานซ้ำซ้อน 100%):** พนักงานตอบอีเมลตามปกติ ระบบจะดูดมาสรุปและอัปเดตลงแดชบอร์ดให้เองอัตโนมัติ
2. **ลดความเสี่ยงค่าปรับหน้างาน (Cost Saving):** งานที่เสี่ยงโดนค่าล่วงเวลารถ (Detention) หรือค่าคืนตู้ช้า (Demurrage) จะถูกดึงขึ้นมาแจ้งเตือนทันที ไม่ตกหล่น
3. **ความโปร่งใสในองค์กร (Operational Transparency):** ทุกคนในบริษัทเปิดหน้าแดชบอร์ดแล้วเห็นภาพเดียวกันทันทีว่าจ๊อบไหนติดที่ใคร ใครต้องเป็นคนขยับต่อ
